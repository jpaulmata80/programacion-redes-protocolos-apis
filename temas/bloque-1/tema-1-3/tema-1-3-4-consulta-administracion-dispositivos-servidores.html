Cómo trabajar este tema

Primero consulta; después administra

La misma automatización que permite leer información puede llegar a modificar muchos equipos. Por eso debes separar operaciones de observación de operaciones de cambio.

1. Organizar un inventario básico de dispositivos.
2. Recorrer varios equipos con una misma función de consulta.
3. Estructurar resultados de éxito y error por dispositivo.
4. Diferenciar consulta, administración y cambios de mayor riesgo.
Alcance. Se trabajan equipos propios o autorizados y operaciones básicas de lectura/administración. Los cambios masivos requieren controles adicionales y no se desarrollan en profundidad aquí.
Explora

De una conexión aislada a una operación sobre inventario

El salto importante consiste en convertir cada equipo en un registro de datos y aplicar una función controlada a todos ellos.

Inventario

Qué equipos existen

Nombre, dirección, tipo, plataforma y datos necesarios para decidir cómo consultar cada dispositivo.

Operación

Qué se permite hacer

Conviene definir comandos o funciones de lectura autorizadas en lugar de aceptar cualquier texto libre.

Resultado

Qué ocurrió

Cada dispositivo debe producir un registro con estado, salida útil, error y momento de ejecución.

Trazabilidad

Cómo se demuestra

La automatización debe dejar evidencia suficiente para saber qué equipo se consultó y con qué resultado.

Separación recomendada: una función puede encargarse de conectar; otra, de ejecutar una consulta; y otra, de guardar resultados. Separar responsabilidades facilita pruebas y reduce errores.

Explica

Inventario + función + resultado

La estructura de datos importa tanto como la conexión.

Inventario básico

dispositivos = [ { "nombre": "srv-noc-01", "host": "192.0.2.10", "tipo": "linux" }, { "nombre": "srv-noc-02", "host": "192.0.2.11", "tipo": "linux" } ]

La dirección usada es de documentación. En un entorno real se usarían equipos autorizados.

Resultado uniforme

def construir_resultado(nombre, estado, salida="", error=""): return { "equipo": nombre, "estado": estado, "salida": salida, "error": error }

Una salida uniforme simplifica reportes y análisis posterior.

Recorrer el inventario

resultados = [] for dispositivo in dispositivos: resultado = consultar_equipo(dispositivo) resultados.append(resultado) for resultado in resultados: print(resultado)

Evitar comandos libres

COMANDOS = { "identidad": "hostname", "uptime": "uptime" } operacion = "identidad" comando = COMANDOS[operacion]

Una lista explícita de operaciones permitidas reduce el riesgo frente a ejecutar texto arbitrario.

Ejercicio resuelto

Consultar dos servidores y consolidar resultados

El objetivo es que un fallo individual no detenga todo el inventario.

Problema

Procesar éxito y error de manera uniforme

1
Definir inventario.
Cada servidor tiene nombre y host.
2
Encapsular la consulta.
Una función recibe un equipo y devuelve un diccionario de resultado.
3
Manejar excepciones por equipo.
Un timeout se registra en ese elemento y el bucle continúa.
4
Consolidar.
Los resultados se almacenan en una lista para generar un resumen final.
def consultar_equipo(dispositivo): try: salida = ejecutar_consulta( dispositivo["host"] ) return { "equipo": dispositivo["nombre"], "estado": "ok", "salida": salida, "error": "" } except Exception as exc: return { "equipo": dispositivo["nombre"], "estado": "error", "salida": "", "error": str(exc) }
Mejora profesional: en código real conviene capturar excepciones específicas (timeout, autenticación, host desconocido) en lugar de depender únicamente de Exception.
