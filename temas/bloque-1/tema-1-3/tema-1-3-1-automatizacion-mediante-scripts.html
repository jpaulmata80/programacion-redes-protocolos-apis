Automatización mediante scripts

Transforma una tarea manual y repetitiva de operación de red en un procedimiento reproducible: entradas claras, lógica verificable, salida útil y registro de resultados.

Cómo trabajar este tema

Automatizar no es solo “hacerlo más rápido”

Un buen script reduce repetición, mejora consistencia y deja una secuencia que puede revisarse, probarse y volver a ejecutarse.

1. Identificar tareas de red que conviene automatizar.
2. Estructurar un script como entrada → proceso → salida.
3. Implementar recorridos básicos sobre listas y archivos.
4. Justificar cuándo automatizar aporta valor y cuándo introduce riesgo.
Alcance. Este subtema se concentra en la lógica general de automatización con Python. La ejecución de comandos de red se desarrollará en 1.3.2 y el acceso remoto por SSH en 1.3.3.
Explora

Los cuatro bloques de un script útil

Antes de escribir código, define qué recibe el script, qué hace con la información, qué entrega y cómo sabrás si funcionó.

Entrada

¿Qué necesita?

Puede recibir direcciones IP, nombres de equipos, parámetros, datos desde un archivo o argumentos escritos por el operador.

Proceso

¿Qué debe hacer?

Validar, recorrer elementos, consultar, transformar datos, tomar decisiones o aplicar una misma operación repetidamente.

Salida

¿Qué produce?

Un mensaje, tabla, archivo, estado, resumen o evidencia que permita interpretar el resultado.

Control

¿Cómo se verifica?

Debe detectar entradas inválidas, registrar errores y evitar continuar silenciosamente cuando algo sale mal.

Principio profesional: si una tarea afecta muchos equipos, automatizarla aumenta el alcance tanto de los aciertos como de los errores. La validación debe crecer junto con la automatización.
Predice

¿Qué tarea automatizarías primero?

Un técnico debe revisar cada mañana 40 equipos y registrar si responden. La tarea es repetitiva, predecible y genera siempre el mismo tipo de resultado.

Piensa en repetición, riesgo y facilidad para comprobar el resultado.

Explica

Una estructura simple y reutilizable

Separar lectura, procesamiento y salida facilita probar cada parte sin mezclar toda la lógica.

Recorrer una lista de equipos

equipos = [ "router-core", "switch-acceso-01", "radio-enlace-01" ] for equipo in equipos: print(f"Procesando: {equipo}")

El bucle expresa la idea central de automatización: aplicar la misma lógica a varios elementos.

Separar responsabilidades

def procesar_equipo(nombre): return { "equipo": nombre, "estado": "pendiente" } def main(): equipos = ["router-01", "router-02"] for equipo in equipos: resultado = procesar_equipo(equipo) print(resultado) if __name__ == "__main__": main()

Una función facilita reutilizar y probar la lógica de un equipo sin repetir código.

Buena práctica inicial: empieza con una operación de lectura o diagnóstico antes de automatizar cambios. Así puedes validar el flujo con menor riesgo.

Generar un inventario básico desde una lista

Partimos de tres equipos y queremos producir una salida uniforme con nombre, tipo y estado inicial.

Problema

Convertir una lista manual en un proceso repetible

1
Entrada.
Definir la lista de equipos.
2
Proceso.
Recorrer cada elemento con for.
3
Estructuración.
Construir un diccionario para mantener una salida consistente.
4
Salida.
Mostrar o guardar el resultado generado.
equipos = [ {"nombre": "RTR-01", "tipo": "router"}, {"nombre": "SW-01", "tipo": "switch"}, {"nombre": "RAD-01", "tipo": "radio"} ] for equipo in equipos: resultado = { "nombre": equipo["nombre"], "tipo": equipo["tipo"], "estado": "por verificar" } print(resultado)
