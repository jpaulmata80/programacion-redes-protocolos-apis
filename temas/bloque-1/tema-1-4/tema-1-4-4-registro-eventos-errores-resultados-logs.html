Registro de eventos, errores y resultados mediante logs

Construye evidencia técnica de lo que hace una aplicación: cuándo se ejecutó una operación, sobre qué equipo, qué resultado obtuvo y qué error ocurrió.

Cómo trabajar este tema

Un log debe servir después, no solo durante la ejecución

La diferencia frente a print() es que el registro incorpora nivel, contexto y formato para poder revisar posteriormente qué sucedió.

1. Diferenciar mensajes informativos, advertencias y errores.
2. Configurar el módulo logging con formato y nivel.
3. Registrar contexto de equipos y operaciones.
4. Conservar evidencia básica en archivos de log.
Alcance. Se introduce logging local con Python. No se abordan todavía plataformas centralizadas de observabilidad, SIEM, syslog avanzado ni rotación compleja.
Explora

Cinco niveles, cinco intenciones

El nivel comunica la importancia operacional del evento.

DEBUG

Detalle técnico

Información útil durante desarrollo o diagnóstico detallado, normalmente demasiado extensa para operación cotidiana.

INFO

Operación normal

Registra hechos esperados: inicio de rutina, consulta completada o resultado correcto.

WARNING

Situación anómala

Algo merece atención, pero la aplicación puede continuar.

ERROR

Operación fallida

Una acción concreta no pudo completarse correctamente.

CRITICAL

Fallo grave

El problema compromete seriamente la continuidad o funcionamiento de la aplicación.

No todo debe ser ERROR. Si todos los eventos tienen la misma severidad, el log pierde capacidad para priorizar.
EventoNivel sugeridoMotivo
Inicio de una rutina programadaINFOEs comportamiento esperado.
Un equipo responde más lento de lo habitualWARNINGHay anomalía, pero no necesariamente fallo.
Autenticación SSH rechazadaERRORLa operación no pudo completarse.

El servicio principal no puede iniciarCRITICALCompromete el funcionamiento global.

Explica

Configurar logging en Python

El módulo logging forma parte de la biblioteca estándar.

Configuración básica

import logging logging.basicConfig( level=logging.INFO, format=( "%(asctime)s | " "%(levelname)s | " "%(message)s" ) ) logging.info("Rutina iniciada")

El formato añade fecha/hora y nivel automáticamente.

Registrar contexto

equipo = "RTR-01" logging.info( "equipo=%s consulta completada", equipo ) logging.warning( "equipo=%s respuesta lenta", equipo )

El estilo con parámetros evita construir la cadena antes de que logging decida emitirla.

Registrar excepciones

try: ejecutar_consulta() except TimeoutError: logging.exception( "Timeout durante la consulta" )

logging.exception() se usa dentro de un except y añade la traza de la excepción.

Guardar en archivo

logging.basicConfig( filename="operacion.log", level=logging.INFO, encoding="utf-8", format=( "%(asctime)s | " "%(levelname)s | " "%(message)s" ) )

El archivo permite conservar evidencia para revisión posterior.

Evita registrar secretos. Contraseñas, claves privadas, tokens o credenciales no deben aparecer en los logs.
Ejercicio resuelto

Registrar una rutina de consulta a tres equipos

Queremos saber qué equipo se consultó, si la operación terminó y qué error ocurrió.

Problema

Conservar evidencia de éxito y fallo

1
Configurar formato.
Fecha, nivel y mensaje.
2
Registrar inicio.
Un evento INFO por equipo.
3
Registrar éxito.
INFO cuando la consulta termina correctamente.
4
Registrar fallo.
ERROR o WARNING según el impacto.
5
Continuar.
El log documenta el fallo sin perder los demás resultados.
import logging logging.basicConfig( level=logging.INFO, format=( "%(asctime)s | " "%(levelname)s | " "%(message)s" ) ) equipos = ["RTR-01", "RTR-02", "RTR-03"] for equipo in equipos: logging.info( "equipo=%s inicio_consulta", equipo ) try: consultar(equipo) logging.info( "equipo=%s resultado=ok", equipo ) except TimeoutError: logging.warning( "equipo=%s resultado=timeout", equipo ) except OSError as exc: logging.error( "equipo=%s error=%s", equipo, exc )
