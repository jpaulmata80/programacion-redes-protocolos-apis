Envío, recepción y estructuración de datos

Un socket mueve bytes. La aplicación decide qué significan esos bytes, cómo se transforman desde datos útiles y cómo se reconstruyen sin ambigüedades al llegar.

Alcance: trabajaremos texto, UTF-8, JSON y una estrategia básica de longitud + contenido. No entraremos todavía en formatos binarios complejos, cifrado, autenticación ni protocolos industriales completos.
EXPLORA

Cuatro transformaciones que una aplicación debe controlar

El error frecuente es creer que send() entiende objetos Python. En realidad, la interfaz de sockets recibe bytes.

Representación

Dato de aplicación

Es lo que tu programa quiere comunicar: una lectura, un estado, un identificador o varios campos relacionados.

  • Ej.: RSSI = -67
  • Ej.: equipo = RTR-07
Serialización

Estructura → texto

Convierte una estructura en una representación intercambiable. JSON es útil para ejemplos legibles e interoperables.

  • json.dumps()
  • json.loads()
Codificación

Texto → bytes

UTF-8 transforma caracteres en bytes antes de enviarlos y permite recuperar el texto al recibirlos.

  • encode("utf-8")
  • decode("utf-8")
Delimitación

¿Dónde termina el mensaje?

En TCP la aplicación observa un flujo de bytes. Debe definir cómo reconocer el inicio y final de cada mensaje.

  • longitud previa
  • delimitador o formato fijo
1Dato
2Serializar

4Transmitir
5Reconstruir
TCP y UDP no se comportan igual: UDP conserva los límites de cada datagrama entregado a la API. TCP entrega un flujo de bytes; una llamada a recv() no equivale necesariamente a “un mensaje completo”.

EXPLICA CON CÓDIGO

Serializar, codificar, enviar y reconstruir

Este ejemplo usa JSON para la estructura y UTF-8 para convertir texto a bytes.

Emisor

import json mensaje = { "equipo": "RTR-07", "rssi": -67, "estado": "operativo" } texto = json.dumps(mensaje) datos = texto.encode("utf-8") sock.sendall(datos)

Idea: json.dumps() produce texto; encode() produce bytes.

Receptor

import json datos = sock.recv(4096) texto = datos.decode("utf-8") mensaje = json.loads(texto) print(mensaje["equipo"]) print(mensaje["rssi"])

Advertencia: este fragmento es didáctico. En TCP real, un solo recv() no garantiza contener exactamente un mensaje completo.

EJERCICIO RESUELTO

Diseñar el mensaje de estado de un radioenlace

Un equipo remoto debe informar identificador, potencia recibida y disponibilidad. Queremos que el receptor pueda interpretar cada campo sin depender de la posición visual del texto.

Situación
Datos: equipo RL-12, RSSI -61.5 dBm, disponibilidad true.
1
Definir campos con significado explícito.
{"equipo":"RL-12","rssi":-61.5,"disponible":true}
2
Serializar.
JSON conserva nombres de campos y tipos básicos, facilitando que otro programa reconstruya la estructura.
3
Codificar a UTF-8.
La cadena JSON se transforma en bytes porque el socket transmite bytes.
4
Definir el límite del mensaje.
Si usamos TCP, una opción robusta es enviar primero una longitud fija que indique cuántos bytes componen el contenido.
5
Reconstruir en orden inverso.
El receptor lee la longitud, reúne exactamente esos bytes, decodifica UTF-8 y aplica json.loads().
Resultado: el receptor obtiene nuevamente una estructura donde puede consultar mensaje["rssi"] sin analizar manualmente una frase.
