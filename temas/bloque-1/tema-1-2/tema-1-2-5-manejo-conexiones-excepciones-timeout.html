Manejo de conexiones, excepciones y tiempos de espera

Una aplicación de red útil no puede asumir que todo funcionará siempre. Debe detectar fallos, evitar bloqueos indefinidos, informar lo ocurrido y liberar correctamente los recursos.

CÓMO TRABAJAR ESTE TEMA

Piensa primero en el fallo y después en la respuesta del programa

No se trata de memorizar nombres de excepciones. El objetivo es decidir qué debe hacer la aplicación ante cada condición anormal.

1 · Configurarun tiempo máximo de espera razonable.
2 · Reconocerfallos frecuentes de conexión y recepción.
3 · Protegerel cierre de sockets y otros recursos.
4 · Diseñarreintentos limitados sin crear bucles infinitos.
Alcance: trabajaremos manejo básico de fallos con sockets bloqueantes en Python. No entraremos todavía en concurrencia, programación asíncrona, backoff exponencial avanzado ni observabilidad distribuida.
EXPLORA

Cuatro mecanismos para que el programa no quede a merced de la red

La red puede fallar por causas externas al código. Un diseño robusto separa el fallo de la respuesta que la aplicación decide tomar.

Tiempo

Timeout

settimeout(segundos) limita cuánto puede esperar una operación bloqueante antes de generar una excepción.

  • Evita esperas infinitas
  • Debe elegirse según el servicio
Detección

Excepciones

Permiten distinguir situaciones como rechazo de conexión, expiración del tiempo o interrupción del enlace.

  • TimeoutError
  • ConnectionRefusedError
Liberación

Cierre seguro

Usar with socket.socket(...) ayuda a cerrar el descriptor aunque ocurra una excepción durante la operación.

  • Evita fugas de recursos
  • Simplifica el flujo
Recuperación

Reintentos limitados

Algunos fallos transitorios justifican intentar nuevamente, pero siempre con un número máximo y una política definida.

  • No ocultar fallos permanentes
  • No crear bucles infinitos
Idea clave: capturar una excepción no significa “ignorar el error”. Significa convertir un fallo técnico en una decisión controlada: reintentar, informar, registrar, usar un valor alternativo o terminar de forma segura.
PREDICE

¿Qué ocurre si el servidor nunca responde?

Un cliente TCP ya está conectado y ejecuta recv(). El servidor permanece activo, pero por un problema lógico no envía ninguna respuesta.

Piensa qué límite temporal conoce el socket si nunca se configuró uno.

EXPLICA CON CÓDIGO

Capturar fallos sin perder el control del programa

El siguiente patrón muestra una consulta TCP sencilla con timeout y cierre automático del socket.

Consulta protegida

import socket try: with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as sock: sock.settimeout(3.0) sock.connect(("192.168.10.20", 5000)) sock.sendall(b"ESTADO") datos = sock.recv(1024) print(datos.decode("utf-8")) except TimeoutError: print("El servicio no respondio a tiempo") except ConnectionRefusedError: print("El destino rechazo la conexion") except OSError as error: print("Fallo de red:", error)

Idea: el bloque with cierra el socket al salir, tanto si todo funciona como si se produce una excepción.

Reintento limitado

import socket import time max_intentos = 3 for intento in range(1, max_intentos + 1): try: with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as sock: sock.settimeout(2.0) sock.connect(("192.168.10.20", 5000)) print("Conexion establecida") break except (TimeoutError, ConnectionRefusedError): print(f"Intento {intento} fallido") if intento < max_intentos: time.sleep(1) else: print("No fue posible conectar")

Importante: un reintento debe tener límite. En sistemas reales también se considera cuándo conviene reintentar y cuánto esperar entre intentos.

EJERCICIO RESUELTO

Consulta de estado a un radio remoto con máximo dos reintentos

Un NOC consulta cada minuto un radio IP. Si el radio no responde en 2 segundos, se permite repetir la consulta hasta dos veces adicionales.

Situación
El programa no debe quedar bloqueado ni reintentar para siempre.
1
Definir el límite temporal.
Configurar sock.settimeout(2.0) antes de las operaciones que pueden bloquear.
2
Definir el número total de intentos.
Un intento inicial + dos reintentos = máximo 3 intentos.
3
Capturar fallos transitorios.
Un TimeoutError o un rechazo temporal pueden conducir a otro intento, mientras quede presupuesto.
4
Cerrar cada socket.
Crear el socket dentro de with asegura su liberación antes del siguiente intento.
5
Producir un resultado final claro.
Si ningún intento funciona, marcar el equipo como “sin respuesta” y continuar con el resto del sistema; no ocultar el fallo.
Conclusión: la robustez no consiste en insistir indefinidamente, sino en limitar la espera, controlar la recuperación y comunicar el estado final.
