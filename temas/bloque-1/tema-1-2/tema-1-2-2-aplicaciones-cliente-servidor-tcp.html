EXPLORA

El servidor publica; el cliente solicita la conexión

TCP es orientado a conexión. Eso obliga a coordinar una secuencia concreta antes de intercambiar datos.

Servidor

bind()

Asocia el socket del servidor con una dirección local y un puerto donde el servicio quedará disponible.

  • Define el extremo local.
  • Puede usar una IP específica o todas las interfaces.
Servidor

listen()

Coloca el socket en modo de escucha para recibir solicitudes de conexión TCP.

  • No acepta todavía una sesión concreta.
  • Prepara la cola de conexiones pendientes.
Servidor

accept()

Extrae una conexión pendiente y devuelve un nuevo socket conectado junto con la dirección del cliente.

  • El socket de escucha permanece separado.
  • El nuevo socket se usa para intercambiar datos.
Cliente

connect()

Solicita una conexión TCP con el extremo remoto definido por dirección IP y puerto.

  • El servidor debe estar disponible.
  • Una conexión exitosa habilita el intercambio.
1Servidorsocket → bind → listen
2Clientesocket → connect
3Servidoraccept devuelve conn, addr
4Ambossendall / recv
5Amboscerrar recursos
Idea clave: en el servidor existen dos sockets con responsabilidades diferentes: el socket de escucha y el socket conectado que devuelve accept(). Confundirlos es un error muy frecuente.

EXPLICA CON CÓDIGO

Un cliente y un servidor TCP mínimos

Lee primero el servidor y luego el cliente. Observa cómo cada llamada corresponde al flujo que acabas de simular.

Servidor TCP

import socket HOST = "127.0.0.1" PORT = 5000 with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as server: server.bind((HOST, PORT)) server.listen() print("Servidor esperando...") conn, addr = server.accept() with conn: print("Cliente conectado:", addr) data = conn.recv(1024) print("Recibido:", data.decode()) conn.sendall(b"ACK desde servidor")

Lectura: server escucha; conn representa la conexión aceptada con ese cliente.

Cliente TCP

import socket HOST = "127.0.0.1" PORT = 5000 with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as client: client.connect((HOST, PORT)) client.sendall(b"Estado del enlace") data = client.recv(1024) print("Respuesta:", data.decode())

Lectura: el cliente conoce el extremo remoto, solicita la conexión, envía bytes y espera una respuesta.

EJERCICIO RESUELTO

Servicio de consulta de estado de un enlace

Traduciremos un requerimiento profesional sencillo a las responsabilidades del servidor y del cliente.

Problema
Un técnico ejecutará un cliente desde su estación de trabajo. El cliente se conectará a 192.0.2.10:5050, enviará la solicitud ESTADO y el servicio devolverá una respuesta textual. ¿Qué debe hacer cada aplicación?
Paso 1 · Identificar roles
El proceso que permanece disponible en 192.0.2.10:5050 actúa como servidor. La herramienta del técnico actúa como cliente porque inicia la conexión.
Paso 2 · Preparar el servidor
Crear un socket TCP, ejecutar bind(("192.0.2.10", 5050)) y después listen(). En un laboratorio local se puede sustituir la dirección por una IP realmente asignada al equipo o por 127.0.0.1 si ambos programas corren en el mismo host.
Paso 3 · Iniciar la conexión
El cliente crea su socket TCP y ejecuta connect(("192.0.2.10", 5050)). El extremo debe coincidir con el servicio publicado.
Paso 4 · Aceptar la sesión
El servidor ejecuta conn, addr = server.accept(). El objeto conn, no el socket de escucha, se usa para la comunicación de esa sesión.
Paso 5 · Intercambiar datos
El cliente envía b"ESTADO"; el servidor recibe, interpreta y responde con bytes. El cliente recibe y decodifica la respuesta.
Paso 6 · Cerrar recursos
Al finalizar, se cierra el socket conectado. El uso de bloques with ayuda a liberar los recursos aunque aparezca una excepción dentro del bloque.

REFERENCIAS Y ALCANCE

Qué consolidamos y qué viene después

Este recurso utiliza la API de sockets de la biblioteca estándar de Python como referencia conceptual. Se concentra en una única conexión TCP y en el intercambio básico de bytes.

  • Python Standard Library: módulo socket.
  • Modelo TCP orientado a conexión: servidor en escucha, cliente que inicia y socket conectado para la sesión.
  • No se desarrolla aquí concurrencia, múltiples clientes, protocolo de aplicación completo ni delimitación avanzada de mensajes.
