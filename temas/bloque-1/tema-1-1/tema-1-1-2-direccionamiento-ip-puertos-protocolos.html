Direccionamiento IP, puertos y protocolos

Una aplicación de red no puede comunicarse solo con “otro computador”. Necesita identificar el destino y el servicio concreto al que desea llegar. Desde la programación, esa decisión se construye combinando dirección IP, puerto y protocolo de transporte.

La IP aproxima el destino de red; el puerto diferencia el servicio dentro del host; el protocolo de transporte completa el contexto del extremo.

Idea clave: dos aplicaciones pueden estar en el mismo host y, aun así, necesitar puertos diferentes. Además, un número de puerto se interpreta dentro de un protocolo de transporte: 53/TCP y 53/UDP no son el mismo extremo.
CONCEPTOS

Tres piezas para localizar el destino lógico de una aplicación

En este subtema trabajaremos con IPv4 para mantener visible la idea principal. IPv6 aparecerá cuando el programa oficial lo requiera.

Dirección IP

Ubica el destino en la red

Desde la perspectiva de una aplicación, la dirección IP permite indicar a qué host o interfaz de red desea enviar tráfico. No identifica por sí sola qué programa debe recibirlo.

  • Ejemplo didáctico: 198.51.100.25.
  • En IPv4 cada octeto válido está entre 0 y 255.
  • La misma IP puede alojar muchos servicios.
Puerto

Diferencia servicios dentro del host

El puerto es un número de 16 bits que permite al sistema operativo asociar tráfico con un servicio o extremo de transporte.

  • Rango: 0–65535.
  • Los puertos conocidos facilitan convenciones, pero una aplicación puede usar otros cuando su diseño lo permite.
  • El puerto remoto indica qué servicio intenta alcanzar el cliente.
Protocolo

Define el contexto de transporte

Para direccionar correctamente el extremo no basta con conocer IP y puerto: también debe saberse qué protocolo de transporte espera el servicio.

  • En este curso trabajaremos principalmente con TCP y UDP.
  • Sus diferencias de comportamiento se estudian en 1.1.3.
  • Aquí nos interesa que forman parte de la identificación del extremo.
Extremo

IP + puerto + transporte

En programación es útil pensar en un extremo remoto como la combinación que indica dónde y a qué servicio queremos llegar.

  • 198.51.100.25:5500/TCP
  • IP: host remoto.
  • 5500: servicio lógico dentro del host.
  • TCP: contexto de transporte.
RangoNombre habitualInterpretación práctica
0–1023Puertos del sistema / bien conocidosIncluyen numerosos servicios estandarizados. Su uso suele estar más controlado por el sistema operativo.
1024–49151Puertos de usuario / registradosPueden asociarse a aplicaciones y servicios registrados o propios.
49152–65535Dinámicos / privadosFrecuentemente se utilizan como puertos temporales de origen elegidos por el sistema operativo.
No memorices listas completas de puertos. Lo importante es aprender a leer documentación, identificar el puerto esperado por un servicio y configurar tu aplicación de forma coherente.

EJERCICIO RESUELTO

Del requisito de la aplicación al extremo de comunicación

Resolveremos un caso completo incluyendo el extremo local y el remoto, sin entrar todavía en programación de sockets.

SituaciónUna aplicación del NOC debe consultar un servicio de telemetría remoto.

Datos proporcionados: cliente 192.0.2.10, puerto local temporal 53214, servidor 198.51.100.25, servicio de telemetría en 5500/TCP.

Paso 1 · Identificar el host remoto
La dirección IP remota es 198.51.100.25. Esta parte permite dirigir el tráfico hacia el host que ofrece el servicio.
Paso 2 · Identificar el servicio remoto
El servicio escucha conceptualmente en el puerto 5500. Esa es la parte que diferencia la telemetría de otros servicios del mismo host.
Paso 3 · Incorporar el transporte
La documentación indica TCP. Por tanto, el extremo remoto se interpreta como 198.51.100.25:5500/TCP.
Paso 4 · Reconocer ambos extremos
El sistema operativo del cliente utiliza el extremo local 192.0.2.10:53214/TCP. La comunicación queda identificada por IP y puerto de origen, IP y puerto de destino y protocolo.
Paso 5 · Formular la 5-tupla
Una forma habitual de describirla es: (TCP, 192.0.2.10, 53214, 198.51.100.25, 5500). El orden exacto al escribirla puede variar según la documentación, pero deben estar presentes protocolo, origen y destino.
Protocolo + IP origen + puerto origen + IP destino + puerto destino
Intenta construir primero el extremo remoto por tu cuenta.
