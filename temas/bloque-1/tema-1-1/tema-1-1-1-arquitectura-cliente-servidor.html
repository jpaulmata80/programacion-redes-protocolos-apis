Arquitectura cliente-servidor

Comprenderemos cómo dos procesos asumen roles diferentes para intercambiar información: uno solicita un servicio y otro lo ofrece. Esta idea aparece detrás de aplicaciones web, monitoreo de red, plataformas de gestión, IoT y numerosos sistemas distribuidos.

Cliente y servidor son roles de software dentro de una interacción. No describen necesariamente tipos de computadoras diferentes.

CONCEPTOS

¿Qué define una arquitectura cliente-servidor?

Más que dos máquinas, hablamos de dos roles coordinados alrededor de un servicio.

Cliente

Solicita un servicio

El cliente inicia una interacción porque necesita un recurso, un dato o una operación proporcionada por otro proceso.

  • Inicia la solicitud.
  • Espera o recibe una respuesta.
  • Interpreta el resultado para continuar su tarea.
Servidor

Ofrece un servicio

El servidor mantiene disponible una funcionalidad y atiende solicitudes provenientes de uno o varios clientes.

  • Permanece disponible para recibir solicitudes.
  • Procesa la petición según reglas del servicio.
  • Devuelve una respuesta o un estado de error.
Solicitud

Expresa una necesidad

Una solicitud comunica qué operación quiere realizar el cliente. En este subtema nos interesa su función conceptual, no todavía su formato ni el protocolo usado.

Respuesta

Comunica el resultado

La respuesta indica el resultado de la solicitud: puede contener datos, una confirmación, un estado o información de error.

Servicio ≠ computadoraUn servicio es una capacidad de software. Puede ejecutarse en un servidor físico, una máquina virtual, un contenedor, un equipo de red o incluso en el mismo computador del cliente.
Rol ≠ identidad permanenteUn programa que responde solicitudes puede posteriormente solicitar datos a otro servicio y asumir, en esa segunda interacción, el rol de cliente.

EJERCICIO RESUELTO

Identificar roles en un sistema de monitoreo

No basta con memorizar “cliente pide y servidor responde”. Debemos identificar los roles dentro de un escenario concreto.

SituaciónUn operador usa un panel del NOC para consultar la temperatura interna de un gabinete remoto.

El panel envía una solicitud a un servicio que se ejecuta en el sitio remoto. El servicio lee el último valor disponible y devuelve “31 °C”.

Paso 1 · Identificar quién inicia
El panel del NOC inicia la consulta. Por tanto, en esta interacción actúa como cliente.
Paso 2 · Identificar quién ofrece la función
El proceso remoto que recibe la consulta y obtiene el dato ofrece el servicio. En esta interacción actúa como servidor.
Paso 3 · Identificar solicitud y respuesta
La solicitud expresa “consultar temperatura”; la respuesta contiene el resultado “31 °C”.
Paso 4 · Formular la conclusión
La arquitectura permite separar al consumidor del servicio de quien lo ofrece. El cliente no necesita realizar localmente la lectura física del sensor; solicita ese resultado al servicio remoto.
Intenta resolver mentalmente el caso antes de revelar el primer paso.
