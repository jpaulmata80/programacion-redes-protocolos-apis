Subtema 1.1.4 · Preparación para desarrollar

Entorno de programación y dependencias

Antes de programar una aplicación de red conviene asegurar que el proyecto tenga un intérprete conocido, un entorno aislado y dependencias controladas. Eso reduce conflictos y permite reproducir el trabajo en otro computador.

Comenzar recorridoVolver al Tema 1.1
ComputadorSistema operativo + instalación de Python
→
Proyecto aisladoEntorno propio + dependencias del proyecto
Runtime: versión con la que se ejecutará el programa.
Entorno virtual: separación lógica de paquetes por proyecto.
Dependencias: paquetes externos necesarios y registrados.
Objetivo profesional: que “funciona en mi computador” se transforme en “puede reproducirse de forma controlada”.

DESARROLLO CONCEPTUAL

Cuatro piezas que conviene no confundir

Un proyecto puede ejecutarse con Python y, al mismo tiempo, utilizar módulos incluidos con Python y otros paquetes instalados aparte.

Runtime

Intérprete y versión

Es el software que ejecuta el programa. Conocer la versión importa porque el lenguaje y las bibliotecas evolucionan.

  • Debe verificarse antes de comenzar.
  • El equipo de trabajo debería acordar una versión compatible.
Aislamiento

Entorno virtual

Es un espacio asociado al proyecto que mantiene sus paquetes separados de otros proyectos.

  • Reduce conflictos entre versiones.
  • Evita depender innecesariamente de paquetes instalados globalmente.
Incluido

Biblioteca estándar

Conjunto de módulos distribuidos con Python. Para los primeros ejercicios de redes, socket, json y ipaddress son ejemplos relevantes.

  • No se instalan con pip por separado.
  • Su disponibilidad depende de la versión de Python.
Externo

Dependencia de terceros

Paquete que el proyecto utiliza pero que no forma parte de la biblioteca estándar. Debe instalarse y conviene registrar su versión.

  • requests es un ejemplo habitual para trabajar con HTTP.
  • El paquete debe instalarse en el entorno correcto.

EJERCICIO RESUELTO

Preparar un proyecto de monitoreo sin mezclar dependencias

El problema no es solo “instalar un paquete”. Debemos poder explicar qué pertenece a Python, qué pertenece al proyecto y cómo otro estudiante reconstruirá el entorno.

SituaciónUn equipo desarrollará una herramienta que consulta direcciones IP, procesa JSON y después consumirá un servicio HTTP.

El proyecto utilizará ipaddress y json, además del paquete externo requests. Dos estudiantes trabajarán en computadores diferentes.

Paso 1 · Identificar qué ya incluye Python
ipaddress y json forman parte de la biblioteca estándar. No se agregan como paquetes externos del proyecto.
Paso 2 · Aislar el proyecto
Se crea un entorno virtual dentro o asociado a la carpeta del proyecto. Así, los paquetes instalados para esta herramienta no interfieren con otros trabajos.
Paso 3 · Instalar solo lo externo
requests sí es una dependencia de terceros. Debe instalarse dentro del entorno virtual activo, no asumirse como disponible globalmente.
Paso 4 · Registrar el estado necesario
Se registra la dependencia en un archivo de requisitos apropiado para este nivel del curso. Así el segundo estudiante conoce qué paquete debe instalar.
Paso 5 · Verificar reproducibilidad
En otro entorno limpio se comprueba que, tras instalar las dependencias registradas, el proyecto puede ejecutarse. Esa prueba es más valiosa que asumir que el archivo de requisitos es correcto.
Antes de revelar cada paso, intenta decidir qué elementos deben instalarse realmente.

CASO PROFESIONAL

Una herramienta del NOC pasa del portátil al servidor

El prototipo funciona en el equipo del desarrollador. Ahora debe ejecutarse en un servidor de operaciones sin copiar manualmente “todo lo que tenga instalado” el portátil.

Situación

  • El proyecto utiliza módulos de la biblioteca estándar.
  • También utiliza dos paquetes externos.
  • En el portátil existen decenas de paquetes globales no relacionados.
  • El servidor debe instalar únicamente lo necesario.

Criterios profesionales

Una preparación reproducible mejora:

  • Trazabilidad: sabemos qué necesita el proyecto.
  • Aislamiento: reducimos interferencias con otras aplicaciones.
  • Despliegue: el servidor recibe lo necesario y no una copia accidental del portátil.
  • Diagnóstico: es más fácil separar errores de instalación de errores de red o de código.
Selecciona una estrategia para el servidor y justifícala con estos criterios.
