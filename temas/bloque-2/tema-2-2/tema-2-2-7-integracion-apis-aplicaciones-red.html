Integración de APIs con aplicaciones de red

Integra datos de servicios externos con información de red para construir herramientas de monitoreo, inventario, diagnóstico y automatización más útiles y resistentes a fallos.

Cómo trabajar este tema

La API es una fuente, no toda la aplicación

Una integración profesional debe separar lógica local, acceso al servicio externo, validación y presentación del resultado.

1. Diseñar un flujo de integración entre una aplicación de red y una API.
2. Combinar datos locales con información obtenida externamente.
3. Aislar el acceso HTTP para facilitar mantenimiento y pruebas.
4. Mantener funcionalidad básica cuando la API externa falla.
Objetivo integrador. Este subtema reúne los aprendizajes de 2.2.1–2.2.6 en una arquitectura sencilla y aplicable a Telecomunicaciones.
Explora

Separar responsabilidades mejora la aplicación

No conviene mezclar consulta HTTP, lógica de negocio, presentación y credenciales en una única función.

La alarma es el dato principal; el inventario es información complementaria.

Explica

Separar el cliente API de la lógica principal

Una función especializada simplifica mantenimiento, pruebas y manejo de errores.

Cliente de inventario

import os import requests def obtener_equipo(equipo_id): token = os.environ["API_TOKEN"] url = ( "https://api.example" f"/v1/equipos/{equipo_id}" ) headers = { "Authorization": f"Bearer {token}", "Accept": "application/json" } try: r = requests.get( url, headers=headers, timeout=5 ) r.raise_for_status() datos = r.json() if not isinstance(datos, dict): return None return datos except requests.RequestException: return None

El acceso HTTP queda concentrado en una función.

Lógica de integración

alarma = { "equipo_id": 452, "evento": "interfaz down" } equipo = obtener_equipo( alarma["equipo_id"] ) resultado = { "evento": alarma["evento"], "equipo_id": alarma["equipo_id"] } if equipo: resultado["sitio"] = equipo.get("sitio") resultado["responsable"] = equipo.get( "responsable" ) else: resultado["inventario"] = ( "no disponible" ) print(resultado)

La alarma se conserva aunque la fuente complementaria falle.

No mezcles secretos con resultados. Tokens y API keys no deben formar parte de diccionarios de salida, reportes ni objetos que luego puedan registrarse.
Ejercicio resuelto

Enriquecer una alarma con inventario

Una alarma local contiene el identificador del equipo. La API corporativa aporta sitio y responsable.

Problema

Integrar dos fuentes sin crear una dependencia frágil

1
Entrada.
Recibir la alarma y extraer equipo_id.
2
Consulta.
Solicitar el recurso correspondiente en la API de inventario.
3
Validación.
Comprobar HTTP, JSON y campos relevantes.
4
Combinación.
Agregar sitio y responsable a la alarma.
5
Degradación.
Si la API falla, conservar la alarma y marcar inventario como no disponible.
Resultado profesional: la API agrega valor, pero no se convierte en un punto único de fallo para una función principal del NOC.
