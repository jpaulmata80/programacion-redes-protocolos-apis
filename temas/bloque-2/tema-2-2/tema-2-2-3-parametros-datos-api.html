Cómo trabajar este tema

No todos los datos se envían de la misma forma

La documentación de la API define qué dato pertenece a la ruta, qué dato es un filtro y qué información debe ir en el cuerpo.

1. Diferenciar parámetros de ruta, query y datos de cuerpo.
2. Enviar parámetros con params= y JSON con json=.
3. Reconocer cuándo se utiliza data= para formularios.
4. Inspeccionar contenido básico recibido en una respuesta HTTP.
Alcance. En este subtema nos centramos en transportar datos. La interpretación detallada de objetos y arreglos JSON se desarrollará en 2.2.4.
Explora

Ruta, query y cuerpo cumplen funciones diferentes

La ubicación de un dato comunica parte de su significado dentro del contrato de la API.

Path

Identificador

Forma parte de la ruta y suele identificar un recurso, por ejemplo /equipos/452.

Query

Filtro o ajuste

Se añade después de ? y suele utilizarse para filtrar, ordenar o paginar.

Body

Contenido enviado

Transporta datos de una operación, por ejemplo un objeto JSON en POST o PATCH.

Response

Contenido recibido

Puede inspeccionarse como texto, bytes o JSON, dependiendo del Content-Type y del contrato.

Explica

Patrones prácticos con requests

La clave está en respetar el formato definido por la API.

Query parameters

import requests url = "https://api.example/v1/enlaces" params = { "zona": "sur", "estado": "up" } respuesta = requests.get( url, params=params, timeout=5 ) print(respuesta.url)

La biblioteca codifica los parámetros y construye la URL final.

Parámetro de ruta

equipo_id = 452 url = ( "https://api.example" f"/v1/equipos/{equipo_id}" ) respuesta = requests.get( url, timeout=5 )

El identificador se incorpora a la ruta porque así lo define el endpoint.

Cuerpo JSON

url = ( "https://api.example" "/v1/equipos/452" ) datos = { "estado": "mantenimiento" } respuesta = requests.patch( url, json=datos, timeout=5 )

json= es adecuado cuando la API espera JSON.

Formulario

url = "https://api.example/v1/sesion" datos = { "usuario": "operador", "modo": "consulta" } respuesta = requests.post( url, data=datos, timeout=5 )

data= no sustituye a json=: úsalo solo si el servicio documenta ese formato.

GET y cuerpo: aunque HTTP no prohíbe universalmente un cuerpo en GET, su semántica e interoperabilidad son problemáticas y muchas implementaciones lo ignoran o rechazan. Para filtros de consulta, utiliza el mecanismo documentado, normalmente query parameters.

Reflexión

Ideas clave

Ruta, query y cuerpo tienen responsabilidades distintas. params=, json= y data= deben utilizarse de acuerdo con el contrato de la API.
