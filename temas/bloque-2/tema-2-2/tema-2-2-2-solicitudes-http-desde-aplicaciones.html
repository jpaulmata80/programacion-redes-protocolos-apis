Cómo trabajar este tema

Construye la solicitud antes de interpretar la respuesta

Una llamada HTTP desde código debe ser explícita: endpoint correcto, método coherente, datos necesarios y un tiempo de espera razonable.

1. Construir solicitudes HTTP básicas desde Python.
2. Enviar parámetros y cabeceras mediante una biblioteca cliente.
3. Controlar tiempos de espera y excepciones básicas.
4. Inspeccionar código de estado y contenido de la respuesta.
Alcance. Usaremos la biblioteca externa requests por claridad didáctica. El procesamiento detallado de JSON se trabajará en 2.2.4 y la autenticación con claves/tokens en 2.2.5.
Explora

Cuatro decisiones antes de enviar

La calidad de la solicitud depende de algo más que escribir una URL.

URL

Endpoint

Debe proceder de la documentación y apuntar al recurso o colección correctos.

Método

Intención

GET consulta, POST envía para crear/procesar, PUT/PATCH actualizan y DELETE solicita eliminar.

Opciones

Parámetros y cabeceras

Se envían mediante argumentos como params y headers.

Control

Timeout

Evita esperar indefinidamente. En requests, el timeout limita esperas de red, no es necesariamente un cronómetro total de toda la operación.

Instalación: requests no forma parte de la biblioteca estándar de Python. Debe instalarse en el entorno del proyecto, por ejemplo con python -m pip install requests.
Predice

¿Qué falta en este cliente?

Un script consulta una API externa con requests.get(url) y no define ningún timeout.

Un servicio externo puede responder lentamente, no responder o sufrir una falla temporal.

Explica

Patrones básicos con requests

La biblioteca ofrece una interfaz simple, pero el cliente sigue siendo responsable de timeout, validación y errores.

GET con parámetros

import requests url = "https://api.example/v1/enlaces" params = { "zona": "sur", "estado": "up" } respuesta = requests.get( url, params=params, timeout=5 ) print(respuesta.status_code) print(respuesta.text)

params construye los parámetros de consulta sin concatenarlos manualmente.

POST con JSON

import requests url = "https://api.example/v1/incidencias" datos = { "enlace": 15, "detalle": "latencia alta" } respuesta = requests.post( url, json=datos, timeout=5 ) print(respuesta.status_code)

json= serializa el objeto y prepara el contenido como JSON.

Manejo inicial de errores

import requests try: respuesta = requests.get( url, timeout=5 ) respuesta.raise_for_status() except requests.Timeout: print("Timeout") except requests.ConnectionError: print("Error de conexión") except requests.HTTPError as exc: print("Respuesta HTTP no exitosa:", exc) except requests.RequestException as exc: print("Error de solicitud:", exc)

raise_for_status() genera una excepción para respuestas HTTP 4xx y 5xx.

Cabeceras básicas

headers = { "Accept": "application/json", "User-Agent": "cliente-noc/1.0" } respuesta = requests.get( url, headers=headers, timeout=5 )

La autenticación se estudiará por separado en 2.2.5.

Buena práctica: no uses verify=False para “resolver” problemas de certificados en código real. Desactivar la validación TLS elimina una protección importante.
Ejercicio resuelto

Consultar enlaces activos de una zona

El NOC necesita consultar enlaces de la zona sur y evitar que el programa se quede esperando indefinidamente.

Problema

Construir una solicitud GET robusta

1
Endpoint.
https://api.example/v1/enlaces
2
Parámetros.
{"zona":"sur","estado":"up"}
3
Timeout.
Definir un valor razonable, por ejemplo 5 s.
4
Enviar.
Usar requests.get(...).
5
Comprobar.
Revisar código de estado antes de procesar el contenido.
import requests url = "https://api.example/v1/enlaces" params = { "zona": "sur", "estado": "up" } try: respuesta = requests.get( url, params=params, timeout=5 ) print("Código:", respuesta.status_code) except requests.Timeout: print("La API no respondió a tiempo") except requests.RequestException as exc: print("Error:", exc)

Ideas clave

Una solicitud desde código combina endpoint, método, parámetros, cabeceras y control de tiempo de espera. La respuesta debe comprobarse antes de utilizar sus datos.
