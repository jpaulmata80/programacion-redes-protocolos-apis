Cómo trabajar este tema

No confíes en la entrada solo porque llegó como JSON

JSON válido únicamente confirma sintaxis. La API debe verificar que los campos, tipos y reglas correspondan al modelo que espera.

1. Modelar cuerpos de solicitud con Pydantic.
2. Validar tipos, campos obligatorios y restricciones.
3. Diferenciar path, query y body en la recepción.
4. Procesar datos validados antes de usarlos.
Alcance. Trabajaremos validación de entrada. La implementación completa de operaciones CRUD se desarrollará en 2.3.4.
Explora

Validar es convertir una entrada externa en un dato utilizable

FastAPI utiliza anotaciones de tipo y modelos Pydantic para comprobar automáticamente gran parte del contrato.

Path

Identificador

Valores como /equipos/{equipo_id} pueden validarse declarando equipo_id: int.

Query

Filtro

Parámetros opcionales o requeridos pueden tiparse y restringirse antes de llegar a la lógica.

Body

Modelo Pydantic

Un BaseModel define los campos que debe contener un cuerpo JSON estructurado.

Procesamiento

Dato limpio

Los tipos declarados forman parte del contrato de entrada.

Explica

Modelos y restricciones con Pydantic

El modelo expresa el contrato del cuerpo antes de que la lógica del endpoint lo utilice.

Modelo básico

from pydantic import BaseModel class EquipoEntrada(BaseModel): nombre: str ip: str activo: bool = True

Los campos sin valor por defecto son obligatorios.

Restricciones con Field

from pydantic import BaseModel, Field class EquipoEntrada(BaseModel): nombre: str = Field( min_length=2, max_length=40 ) prioridad: int = Field( ge=1, le=5 )

ge y le permiten establecer límites numéricos.

Validar una dirección IP

from ipaddress import IPv4Address from pydantic import BaseModel class EquipoEntrada(BaseModel): nombre: str ip: IPv4Address

Usar un tipo específico evita aceptar cualquier cadena como dirección IPv4.

Recibir el body

@app.post("/api/equipos") def crear_equipo( equipo: EquipoEntrada ): return { "recibido": equipo.model_dump() }

En Pydantic v2, model_dump() convierte el modelo en un diccionario Python.

Query con restricción

from fastapi import Query @app.get("/api/equipos") def listar_equipos( limit: int = Query( default=20, ge=1, le=100 ) ): return { "limit": limit }

La API rechaza valores fuera del rango declarado.

Procesar después de validar

@app.post("/api/equipos") def crear_equipo( equipo: EquipoEntrada ): nombre_normalizado = ( equipo.nombre.strip().upper() ) return { "nombre": nombre_normalizado, "ip": str(equipo.ip), "activo": equipo.activo }

La transformación ocurre sobre datos que ya superaron la validación del modelo.

No confundir validación con lógica de negocio. Comprobar que prioridad esté entre 1 y 5 es validación de formato/regla. Comprobar si un equipo ya existe en inventario pertenece a la lógica del servicio.
Ejercicio resuelto

Registrar un equipo de red

La API recibe nombre, IPv4, prioridad y estado inicial.

Problema

Validar antes de procesar

1
Definir modelo.
Nombre, IPv4, prioridad y estado.
2
Restringir.
Nombre mínimo 2 caracteres; prioridad entre 1 y 5.
3
Recibir body.
Usar el modelo como parámetro del endpoint.
4
Procesar.
Normalizar el nombre.
5
Responder.
Devolver representación coherente del dato aceptado.
from ipaddress import IPv4Address from fastapi import FastAPI from pydantic import BaseModel, Field app = FastAPI() class EquipoEntrada(BaseModel): nombre: str = Field( min_length=2, max_length=40 ) ip: IPv4Address prioridad: int = Field( ge=1, le=5 ) activo: bool = True @app.post("/api/equipos") def crear_equipo( equipo: EquipoEntrada ): return { "nombre": equipo.nombre.strip().upper(), "ip": str(equipo.ip), "prioridad": equipo.prioridad, "activo": equipo.activo }
