Cómo trabajar este tema

CRUD describe operaciones; HTTP expresa la interacción

CRUD y métodos HTTP se relacionan con frecuencia, pero no son conceptos idénticos. El diseño debe mantener semántica coherente sobre los recursos.

1. Implementar creación y consulta de recursos.
2. Actualizar parcialmente un recurso existente.
3. Eliminar recursos identificados.
4. Mantener coherencia entre rutas, métodos y datos.
Alcance. Usaremos almacenamiento en memoria para concentrarnos en la lógica CRUD. Una base de datos real introduciría persistencia, concurrencia y transacciones adicionales.
Explora

Una operación CRUD siempre actúa sobre un recurso

El endpoint debe identificar claramente colección o recurso individual antes de ejecutar la operación.

Create

Crear

Normalmente se usa POST sobre la colección para incorporar un nuevo recurso.

Read

Consultar

GET puede recuperar la colección completa o un recurso individual.

Update

Actualizar

PATCH suele utilizarse para cambios parciales; PUT puede representar reemplazo completo según el contrato.

Delete

Eliminar

DELETE solicita eliminar el recurso identificado por la ruta.

CRUD no define por sí solo una API REST. Es una forma útil de organizar operaciones, pero el diseño REST también depende de recursos, representaciones, semántica HTTP y otros principios.

Explica

CRUD en memoria con FastAPI

El almacenamiento simulado permite concentrarse en la lógica del endpoint.

Modelo y almacenamiento

from fastapi import FastAPI from pydantic import BaseModel app = FastAPI() class EquipoEntrada(BaseModel): nombre: str estado: str equipos = [ { "id": 1, "nombre": "RTR-AZG-01", "estado": "up" } ]

La lista existe solo mientras el proceso está activo.

Create

@app.post("/api/equipos") def crear_equipo( equipo: EquipoEntrada ): nuevo_id = len(equipos) + 1 nuevo = { "id": nuevo_id, **equipo.model_dump() } equipos.append(nuevo) return nuevo

El ID generado así es didáctico; no es una estrategia robusta para producción.

Read

@app.get("/api/equipos") def listar_equipos(): return { "items": equipos } @app.get("/api/equipos/{equipo_id}") def obtener_equipo( equipo_id: int ): for equipo in equipos: if equipo["id"] == equipo_id: return equipo return None

En 2.3.5 se reemplazará None por una respuesta HTTP apropiada.

Update parcial

class EquipoPatch(BaseModel): nombre: str | None = None estado: str | None = None @app.patch("/api/equipos/{equipo_id}") def actualizar_equipo( equipo_id: int, cambios: EquipoPatch ): for equipo in equipos: if equipo["id"] == equipo_id: datos = cambios.model_dump( exclude_none=True ) equipo.update(datos) return equipo return None

exclude_none=True evita reemplazar campos no enviados por None.

Delete

@app.delete("/api/equipos/{equipo_id}") def eliminar_equipo( equipo_id: int ): for indice, equipo in enumerate(equipos): if equipo["id"] == equipo_id: eliminado = equipos.pop(indice) return eliminado return None

La eliminación modifica la colección almacenada en memoria.

Limitación didáctica: esta lista no ofrece persistencia, aislamiento entre procesos ni control de concurrencia. Su objetivo es enseñar el flujo CRUD antes de introducir almacenamiento real.
