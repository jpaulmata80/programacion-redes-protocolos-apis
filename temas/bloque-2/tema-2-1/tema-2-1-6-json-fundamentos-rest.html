Explora

JSON organiza datos; REST organiza una arquitectura

Son conceptos relacionados en muchas APIs, pero no significan lo mismo.

JSON

Representación de datos

Formato textual estructurado basado en objetos, arreglos, cadenas, números, booleanos y null.

Recurso

Entidad conceptual

Puede representar un enlace, una alarma, una estación, una incidencia o cualquier entidad expuesta por el servicio.

URI

Identificador

Permite referirse a un recurso dentro de la interfaz, por ejemplo /api/enlaces/15.

REST

Estilo arquitectónico

Promueve una interfaz uniforme, separación cliente-servidor, comunicación sin estado de sesión del cliente en el servidor y recursos manipulados mediante representaciones.

Importante: REST no obliga a utilizar JSON. Una representación podría usar otros formatos. JSON es popular porque es simple y ampliamente soportado.

Observa y explica

El mismo recurso puede tener distintas operaciones

La URI identifica el recurso; el método expresa qué deseas hacer con él.

Consultar

GET /api/enlaces/15 Accept: application/json → 200 OK {"id":15,"estado":"up"}

El servidor devuelve una representación del estado actual del recurso.

Modificar parcialmente

PATCH /api/enlaces/15 Content-Type: application/json {"descripcion":"Enlace principal"}

El cliente solicita cambiar únicamente una parte del recurso.

Eliminar

DELETE /api/enlaces/15 → 204 No Content

El cliente solicita eliminar el recurso; la API decide si la operación está permitida.

Colección

GET /api/enlaces?zona=sur Accept: application/json → 200 OK [{"id":15},{"id":18}]

Una colección puede representarse como un arreglo JSON.

No toda API HTTP es REST. Usar HTTP y devolver JSON no basta por sí solo para afirmar que una interfaz cumple los principios REST.

Ideas clave

JSON representa datos. REST es un estilo arquitectónico orientado a recursos, interfaz uniforme y comunicación sin estado de sesión del cliente entre solicitudes.
