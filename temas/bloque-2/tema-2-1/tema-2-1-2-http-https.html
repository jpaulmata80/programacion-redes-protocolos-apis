HTTP y HTTPS

Comprende cómo HTTP organiza la comunicación entre aplicaciones web y qué añade HTTPS mediante TLS para proteger la información mientras viaja entre cliente y servidor.

Cómo trabajar este tema

Separa protocolo de aplicación y protección del canal

HTTP define cómo se intercambian mensajes web. HTTPS no es “otro HTTP”: es HTTP utilizado sobre una comunicación protegida mediante TLS.

1. Explicar qué función cumple HTTP en una aplicación web.
2. Diferenciar HTTP de HTTPS sin confundirlos con TCP o UDP.
3. Relacionar TLS con cifrado, integridad y autenticación.
4. Justificar por qué los servicios web modernos deben proteger información sensible en tránsito.

Explora

Cuatro conceptos que no deben confundirse

Distinguir capas evita errores frecuentes al explicar cómo funciona un servicio web.

HTTP

Protocolo de aplicación

Define la estructura conceptual de solicitudes y respuestas entre clientes y servidores web.

HTTPS

HTTP protegido

Utiliza TLS para proteger la comunicación HTTP en tránsito.

TLS

Seguridad del canal

Aporta confidencialidad, integridad y autenticación del servidor; puede incluir autenticación del cliente en ciertos escenarios.

Transporte

Debajo de HTTP

HTTP/1.1 y HTTP/2 usan normalmente TCP; HTTP/3 utiliza QUIC, que funciona sobre UDP.

Convención de puertos: HTTP utiliza habitualmente el puerto 80 y HTTPS el 443, aunque un servicio puede configurarse en otros puertos.

HTTP

  • No proporciona por sí mismo cifrado del contenido.
  • El esquema habitual es http://.
  • Puede ser útil en entornos controlados de laboratorio.
  • No debe utilizarse para transmitir secretos en una red no confiable.

HTTPS

  • Protege el contenido HTTP mediante TLS.
  • El esquema habitual es https://.
  • Permite validar la identidad del servidor mediante certificados.
  • Reduce el riesgo de lectura o modificación del contenido en tránsito.

Observa y explica

La URL también comunica el esquema

El inicio de la URL indica si la comunicación web se plantea con HTTP o HTTPS.

HTTP

http://monitor.example/api/enlaces/15

La aplicación utiliza HTTP sin la protección que proporciona TLS.

HTTPS

https://monitor.example/api/enlaces/15

La aplicación utiliza HTTP protegido mediante TLS.

No confundas HTTPS con “sitio confiable”. HTTPS protege el canal y permite validar la identidad presentada por el servidor; no garantiza que el contenido de la aplicación sea correcto, seguro o legítimo por sí mismo.
Ejercicio resuelto

Acceso a una plataforma de gestión

Un operador debe consultar alarmas y autenticarse en una plataforma web desde una red que no controla.

Problema

Elegir HTTP o HTTPS y justificar

1
Identificar sensibilidad.
Se transmitirán credenciales y datos operativos.
2
Evaluar la red.
El operador no controla todos los sistemas intermedios.
3
Elegir HTTPS.
Se necesita protección del contenido en tránsito.
4
Validar el servidor.
El cliente debe comprobar correctamente el certificado presentado.
5
Reconocer límites.
HTTPS no corrige vulnerabilidades de la aplicación ni protege un endpoint comprometido.
Conclusión: para una plataforma operativa con autenticación, HTTPS debe ser la opción normal porque protege la comunicación en tránsito mediante TLS.

Reflexión

¿Qué riesgos tendría usar HTTP en una plataforma operativa?

Piensa en credenciales, datos de monitoreo, redes compartidas y posibilidad de modificación del tráfico en tránsito.

Ideas clave

HTTP organiza el intercambio web. HTTPS utiliza TLS para proteger la comunicación en tránsito y autenticar al servidor mediante certificados.
