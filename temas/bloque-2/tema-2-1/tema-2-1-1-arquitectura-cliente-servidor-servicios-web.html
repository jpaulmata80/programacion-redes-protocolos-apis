Arquitectura cliente-servidor aplicada a servicios web

Comprende cómo una aplicación cliente solicita información o servicios, cómo el servidor procesa la solicitud y cómo ambos intercambian mensajes dentro de una arquitectura web.

Modelo fundamental

Cliente inicia la interacción
→
Petición solicita un recurso o una operación
Servidor recibe, procesa y decide
→
Respuesta devuelve resultado y contenido
Cliente interpreta el resultado
←
Recurso estado · datos · representación

Explora

Cinco piezas del modelo

Comprender estas piezas permite interpretar después cualquier intercambio HTTP.

Cliente

Quien solicita

Puede ser un navegador, una aplicación móvil, un script Python o incluso otro servidor.

Servidor

Quien atiende

Escucha solicitudes, ejecuta lógica, consulta datos y construye una respuesta.

Petición

Mensaje de entrada

Describe qué desea realizar el cliente sobre un recurso.

Respuesta

Mensaje de salida

Comunica el resultado y, cuando corresponde, transporta datos al cliente.

Recurso. Es la entidad o información que el servicio expone conceptualmente: un enlace, una alarma, un usuario, una estación, una métrica o un registro.
Interfaz cliente Presenta información o inicia operaciones.
Lógica del servidor Valida, consulta, procesa y decide qué responder.
Datos / servicios internos Base de datos, sistema de monitoreo u otros servicios.
Un servidor también puede ser cliente. Si un servidor web consulta a otro servicio externo para completar una respuesta, actúa como cliente en esa segunda interacción.
Predice

¿Quién inicia?

Una aplicación del NOC necesita consultar el estado actual de un enlace registrado en una plataforma web.

Piensa en el flujo petición → procesamiento → respuesta.

Observa y explica

La misma arquitectura vista como intercambio

Todavía no necesitas memorizar sintaxis HTTP; concéntrate en reconocer roles y dirección del flujo.

Petición conceptual

Cliente: "Necesito el recurso enlace 15" Destino: Servidor de gestión

El cliente conoce qué recurso desea consultar y envía una solicitud al servicio.

Respuesta conceptual

Servidor: "Encontré el enlace 15" Resultado: estado = up sitio = AZG-01

El servidor procesa la solicitud y devuelve una representación del recurso.

Separación de responsabilidades: el cliente no necesita conocer cómo se almacenó internamente el enlace; el servidor encapsula esa lógica y ofrece una interfaz de acceso.
Ejercicio resuelto

Modelar una consulta de disponibilidad

Una aplicación universitaria desea consultar si una estación de telecomunicaciones está operativa.

Problema

Identificar componentes de la arquitectura

1
Cliente.
Aplicación utilizada por el operador.
2
Recurso.
La estación cuyo estado desea consultarse.
3
Petición.
El cliente solicita información del recurso.
4
Servidor.
La aplicación de gestión recibe la solicitud y consulta su fuente de datos.
5
Respuesta.
El servidor devuelve el estado disponible de la estación.
Resultado: el cliente conoce la interfaz ofrecida por el servicio, pero no necesita acceder directamente a la base de datos ni conocer su implementación interna.

Ideas clave

Cliente y servidor son roles lógicos. La interacción se organiza alrededor de una petición, un recurso, procesamiento del servidor y una respuesta.
