Métodos HTTP: GET, POST, PUT/PATCH y DELETE

Aprende a expresar la intención de una operación sobre un recurso: consultar, crear o procesar, reemplazar, modificar parcialmente o eliminar.

Comenzar recorrido Volver al Tema 2.1

Una intención para cada operación

GETobtener una representación de un recurso
POSTenviar datos para crear o procesar según el servicio
PUTcrear o reemplazar completamente una representación en una URI conocida
PATCHaplicar una modificación parcial
DELETEsolicitar la eliminación de un recurso
Cómo trabajar este tema

El método comunica intención

Una misma ruta puede admitir distintas operaciones. El método permite al servidor interpretar qué desea hacer el cliente.

1. Diferenciar GET, POST, PUT, PATCH y DELETE según su propósito.
2. Seleccionar un método coherente con una operación sobre recursos.
3. Interpretar seguridad e idempotencia a nivel conceptual.
4. Modelar operaciones HTTP aplicadas a recursos de Telecomunicaciones.
Alcance. Se estudia la semántica de los métodos. Los códigos de estado que indican el resultado de cada operación se desarrollarán en 2.1.4.
Explora

Cinco métodos, cinco responsabilidades

Elegir bien el método hace que una API sea más predecible y comprensible.

GET

Consultar

Solicita una representación del recurso. Semánticamente es seguro e idempotente.

POST

Crear o procesar

Envía datos para que el servidor los procese. Su efecto depende del servicio y no es necesariamente idempotente.

PUT

Reemplazar

Se utiliza para crear o reemplazar completamente el estado del recurso identificado por la URI. Es idempotente por semántica.

PATCH

Modificar parcialmente

Aplica cambios parciales sobre un recurso. No es necesariamente idempotente.

DELETE

Eliminar

Solicita eliminar el recurso identificado. Es idempotente por semántica, aunque respuestas posteriores puedan variar.

Seguro no significa cifrado. En HTTP, un método “seguro” es aquel cuya semántica pretende ser de solo lectura. GET es seguro; POST, PUT, PATCH y DELETE no lo son.

Observa y explica

Una misma colección, diferentes operaciones

La ruta y el método trabajan juntos para expresar la intención.

Consultar un recurso

GET /api/enlaces/15

Solicita la representación actual del enlace 15.

Crear dentro de una colección

POST /api/incidencias

Envía datos para crear o procesar una nueva incidencia según la API.

Reemplazar

PUT /api/enlaces/15

El cliente envía una representación destinada a reemplazar el estado del recurso.

Modificar parcialmente

PATCH /api/enlaces/15

El cliente solicita cambiar únicamente determinados campos.

Eliminar

DELETE /api/enlaces/15

Solicita la eliminación del recurso identificado.

Ideas clave

El método HTTP comunica la intención de una operación. GET es seguro e idempotente; PUT y DELETE son idempotentes; POST y PATCH no lo son necesariamente.

Delimitación
