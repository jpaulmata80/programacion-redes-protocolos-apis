Cómo trabajar este tema

Cada dato tiene un lugar y una función

Las cabeceras describen cómo debe interpretarse o procesarse el mensaje. Los parámetros ajustan la consulta o identifican recursos dentro de la interfaz.

Explora

Cuatro componentes frecuentes

Identificar cada uno ayuda a leer documentación de APIs con mucha más facilidad.

Header

Accept

Indica qué tipo de representación puede recibir el cliente, por ejemplo application/json.

Header

Content-Type

Describe el formato del contenido que realmente se envía en el cuerpo del mensaje.

Header

Authorization

Transporta información de autenticación según el esquema definido por el servicio. No debe exponerse en logs o URLs.

Parámetro

Consulta y ruta

Permiten filtrar, ordenar, paginar o identificar un recurso específico.

Accept vs Content-Type. Accept expresa qué quiere recibir el cliente. Content-Type describe qué formato tiene el contenido que se está enviando.

Seguridad. Tokens, contraseñas y secretos no deben colocarse en parámetros de consulta porque pueden quedar registrados en historiales, proxies o logs. La autenticación debe seguir el mecanismo definido por la API y utilizar HTTPS.

Observa y explica

Ruta, query y cabeceras cumplen funciones diferentes

Separar responsabilidades hace que una API sea más predecible.

Recurso individual

GET /api/enlaces/15 Accept: application/json

El identificador 15 forma parte de la ruta y selecciona un recurso concreto.

Colección filtrada

GET /api/enlaces?estado=alerta Accept: application/json

El parámetro de consulta filtra la colección sin cambiar su identidad básica.

Enviar JSON

POST /api/incidencias Content-Type: application/json {"enlace":15,"detalle":"latencia alta"}

Content-Type describe el formato del cuerpo enviado.

Solicitar JSON

GET /api/alarmas Accept: application/json

Accept indica el formato que el cliente desea recibir.

Ejercicio resuelto

Consultar alarmas críticas de una zona

El NOC necesita consultar una colección y aplicar dos filtros sin modificar los datos.

Problema

Construir la solicitud correcta

1
Método.
GET, porque se trata de una consulta.
2
Ruta.
/api/alarmas, porque se consulta la colección.
3
Filtros.
?severidad=critica&zona=sur.
4
Formato esperado.
Accept: application/json.
5
Seguridad.
Si el recurso está protegido, la credencial se envía según el mecanismo de autenticación de la API y sobre HTTPS.
GET /api/alarmas?severidad=critica&zona=sur HTTP/1.1 Host: noc.example Accept: application/json Authorization: Bearer <token>
Nota: la sintaxis concreta de filtros depende de la documentación de cada API. No existe un conjunto universal de nombres de parámetros.
