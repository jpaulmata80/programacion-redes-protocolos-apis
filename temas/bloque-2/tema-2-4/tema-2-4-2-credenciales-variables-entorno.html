Gestión segura de credenciales y variables de entorno

Separa secretos y configuración del código fuente para reducir exposición accidental de API keys, tokens, usuarios y contraseñas en aplicaciones de red.

Cómo trabajar este tema

La seguridad empieza evitando exposición innecesaria

Una credencial hardcodeada puede terminar en Git, capturas, logs, archivos compartidos o copias antiguas del proyecto.

1. Identificar prácticas inseguras de manejo de secretos.
2. Leer configuración sensible desde variables de entorno.
3. Evitar exposición en código, logs y repositorios.
4. Aplicar principios básicos de rotación y mínimo privilegio.
Alcance. Las variables de entorno reducen exposición en el código, pero no son un gestor de secretos completo. En sistemas de mayor criticidad se utilizan soluciones específicas de gestión de secretos.
Explora

Configuración y secretos no son código

La aplicación necesita conocer credenciales para operar, pero eso no implica almacenarlas dentro del repositorio.

Secreto

Credencial

API key, token, contraseña o clave privada que permite acceso a un recurso.

Entorno

Configuración externa

Valores suministrados al proceso sin modificar el código fuente.

Principio

Mínimo privilegio

Una credencial debería tener únicamente los permisos necesarios para la tarea que realiza.

Ciclo de vida

Rotación

Si un secreto se expone o deja de ser apropiado, debe reemplazarse y revocarse cuando corresponda.

Explica

Configuración sensible fuera del código

Python puede leer variables de entorno sin necesidad de almacenar el secreto dentro del archivo fuente.

Leer una variable obligatoria

import os TOKEN = os.environ[ "INVENTARIO_TOKEN" ]

Si la variable no existe, se produce un error inmediatamente. Esto puede ser útil para detectar configuración incompleta.

Leer configuración opcional

import os BASE_URL = os.getenv( "INVENTARIO_URL", "https://api.example/v1" )

os.getenv() permite definir un valor por defecto cuando tiene sentido hacerlo.

Usar el token sin imprimirlo

headers = { "Authorization": f"Bearer {TOKEN}", "Accept": "application/json" } response = requests.get( f"{BASE_URL}/equipos/452", headers=headers, timeout=5 )

No muestres headers completos en logs si contienen credenciales.

Archivo .env local

# .env INVENTARIO_TOKEN=valor_local INVENTARIO_URL=https://api.example/v1 # .gitignore .env

Un .env puede ser útil en desarrollo, pero debe permanecer fuera del repositorio cuando contiene secretos.

Archivo de ejemplo

# .env.example INVENTARIO_TOKEN= INVENTARIO_URL=https://api.example/v1

El archivo de ejemplo documenta las variables requeridas sin compartir valores reales.

Fallo seguro de configuración

import os token = os.getenv( "INVENTARIO_TOKEN" ) if not token: raise RuntimeError( "Falta INVENTARIO_TOKEN" )

Es preferible detectar una configuración incompleta que ejecutar con una credencial vacía o inventada.

Importante: las variables de entorno no son invisibles ni invulnerables. Procesos con permisos suficientes, volcados de memoria o configuraciones deficientes pueden exponerlas. Son una práctica básica de separación, no una solución total.

Problema

Separar credencial, configuración y lógica

1
Eliminar secreto del código.
No mantener tokens literales en el archivo Python.
2
Definir variable externa.
INVENTARIO_TOKEN.
3
Leer al iniciar.
Detectar si la configuración falta.
4
Usar en Authorization.
Sin imprimir el valor.
5
Si se expuso.
Revocar y reemplazar la credencial; moverla de archivo no invalida una copia ya comprometida.
import os import requests TOKEN = os.environ[ "INVENTARIO_TOKEN" ] def obtener_equipo(equipo_id): headers = { "Authorization": ( f"Bearer {TOKEN}" ) } response = requests.get( "https://api.example" f"/v1/equipos/{equipo_id}", headers=headers, timeout=5 ) return response
