Explora

Tres preguntas diferentes: ¿cómo ejecuto?, ¿cómo aprovecho recursos?, ¿cómo crezco?

Despliegue, eficiencia y escalabilidad están relacionados, pero no significan lo mismo.

Despliegue

Ejecutar de forma controlada

Configurar dependencias, variables, proceso de servicio, red y observación.

Eficiencia

Usar bien los recursos

Evitar esperas innecesarias, cargas excesivas, consultas repetidas y respuestas sin límites.

Vertical

Más capacidad por instancia

Aumentar CPU, memoria u otros recursos disponibles para el mismo nodo.

Horizontal

Más instancias

Distribuir solicitudes entre varias instancias de la aplicación.

Predice

¿Qué problema aparece al escalar horizontalmente?

Dos instancias de la API guardan equipos en una lista Python propia.

El estado almacenado dentro del proceso no se comparte automáticamente entre instancias.

Fundamentos prácticos para ejecutar y crecer

Las decisiones de despliegue deben conservar el contrato HTTP y mejorar la operación, no cambiar la lógica arbitrariamente.

Desarrollo

uvicorn main:app --reload

--reload facilita el desarrollo al reiniciar el servidor cuando cambian archivos. No es una configuración de producción.

Ejecución sin reload

uvicorn main:app \ --host 0.0.0.0 \ --port 8000

0.0.0.0 permite escuchar en interfaces de red disponibles; no aporta seguridad por sí mismo. Firewall, TLS y exposición de red deben configurarse aparte.

Timeout en dependencias

response = requests.get( url, headers=headers, timeout=5 )

El timeout evita esperas indefinidas. Su valor debe ajustarse al comportamiento esperado del servicio.

Reutilizar conexiones HTTP

import requests session = requests.Session() response = session.get( url, timeout=5 )

Una sesión puede reutilizar conexiones en múltiples solicitudes al mismo servicio, reduciendo sobrecarga en ciertos flujos.

Limitar resultados

@app.get("/api/equipos") def listar_equipos( limit: int = 50, offset: int = 0 ): return { "items": equipos[ offset:offset + limit ] }

La paginación evita devolver colecciones arbitrariamente grandes. En producción debe acompañarse de validación y persistencia adecuada.

Estado externo compartido

# Idea conceptual API instancia A ─┐ ├─> almacenamiento compartido API instancia B ─┘

Cuando varias instancias necesitan compartir datos, el estado no debería depender únicamente de una lista en memoria de cada proceso.

Concurrencia no significa automáticamente escalabilidad. Atender varias solicitudes concurrentes ayuda con cargas de I/O, pero la capacidad total sigue limitada por CPU, memoria, dependencias y diseño de la aplicación.
